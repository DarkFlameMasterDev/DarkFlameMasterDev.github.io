图片引入

hexo 官方给了 3 种引入图片的方式，在我看来，其实都大差不差

1.全局资源文件夹

最简单的方法就是将它们放在 source/images 文件夹中。 然后通过类似于 ![](/images/image.jpg) 的方法访问它们。

2.文章资源文件夹

通过将 config.yml 文件中的 post_asset_folder 选项设为 true 来打开。

如果没有，那就在自己添加一下，但我强烈建议你使用 hexo-renderer-markdown-it

相对路径引用的标签插件

启用后，资源图片将会被自动解析为其对应文章的路径。 例如： image.jpg 位置为 /2020/01/02/foo/image.jpg ，这表示它是 /2020/01/02/foo/ 文章的一张资源图片， ![](image.jpg) 将会被解析为 <img src="/2020/01/02/foo/image.jpg"> 。

使用 Markdown 嵌入图片

hexo-renderer-marked 3.1.0 引入了一个新的选项，其允许你无需使用 asset_img 标签插件就可以在 markdown 中嵌入图片

这几种方法弊端都是本地无法预览，你在本地编辑博客的时候无法预览图片，而且 hexo g 的时候文件太大，博客一旦多了就会等待几十秒甚至达到分钟级别

3. 配置图床

配置图床可以将文件上传，然后所有图片全用链接来引入，因为图片并不是一直在调整的，经常是导入一张图片，后面就再也不管了。现在的图床对于去重和排序重命名做得很好。也足够便宜，还是很值得尝试的。

选择一：Cloudflare R2（目前口碑最好，推荐首选）

  • 免费额度：10GB 存储、每月 100 万次上传（A 类操作）、1000 万次读取（B 类操作），关键是出口流量完全免费。
  • 个人博客几百张图一般占用不到 2GB，够用好几年。
  • 优点：大厂背书不易跑路、兼容 S3 API 可随时迁移、不需要备案，配合 PicGo 上传体验很流畅。
  • 缺点：开通需要绑定信用卡/PayPal 验证身份（不会自动扣费），国内直连速度一般，建议自己套一层 Cloudflare 自定义域名+缓存规则来加速和省流量。这也是为什么后台把 GitHub+jsDelivr、SM.MS 等方案都比下去的原因——jsDelivr 在国内已被封锁 DNS 污染，图片经常裂图；免费公共图床则有随时删图/跑路的风险。

搭建流程大致是：注册 Cloudflare → 开 R2 → 建 Bucket → 配置公开访问（测试可用 r2.dev 子域，正式建议绑自定义域名）→ 建 API 令牌 → PicGo 装 S3 插件填入 AccessKey/Secret/Bucket/Endpoint → 测试上传

自己买个域名大概一年会耗费 10 刀左右，也就是 66 块钱，还是很值的。用过你就知道写博客时候的顺畅感太重要了
另外，hexo 并不能完美在你修改之后进行 html 的实时渲染，尤其是你修改了配置文件。
在渲染出错的时候，可以直接进入本地的 public/ 里查看实际生成的内容。

可以查看我的 Cloudflare R2 图床配置

选择二：国内云服务商免费额度（七牛云等）

七牛云等也有约 10GB 免费额度，速度稳定。
但绑自己域名基本都要求备案，流程繁琐，个人博客图省事的话不太友好。
还有 get 次数有限制目前是每月 100 万次，其实也够用。

这种写法缺点：

  1. 修改标题后链接失效
  2. 文章标题五花八门会进行 slug 处理
    “文章 跳转” 会被改成 “文章-跳转”，因为不允许有空格，所以最好你点过去试一下，看看浏览器地址栏，再选择怎么写

文章跳转不涉及标题

{% post_link linux-command Linux 命令详解 %}

其中 linux-command 是文章名 Linux 命令详解 是显示的可点击的链接文字

跳转到指定标题

{% post_link linux-command#总结 Linux 命令详解 总结 %}

在文章名后直接加 #标题 就好了，但是依旧需要 slug 处理字符

有很多文章推荐使用 HTML，我感觉违背了写博客的初衷，而且过于复杂的页面也不好维护，简单就是最好的。

但是，Markdown 不允许使用相同的标题，这会使得跳转的时候出错，但无所谓了，这个功能本身就很粗糙。凑合着用吧。

个人使用习惯

开始使用 codespaces

我总感觉配置博客是一个很麻烦的事情，如果能配置一次以后不需要大调整就最好了，所以我就把博客系统托管了，考虑买个 VPS 的，但又感觉有点贵，最后选择了 github 的 codespaces ，弊端是限制时间，优点是写博客不需要耗太多时间，只需要将博客在本地写好，然后再在 codespaces 调整一下格式然后提交就行。

这也是我最关心的，写博客只关注博客本身就好了，频繁修改格式会打扰思路，这样将写内容和调整格式，反而可以更顺畅的来写博客
